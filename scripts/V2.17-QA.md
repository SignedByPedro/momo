# v2.17 - Natural Conversation Upgrade: manual acceptance checks

Run after `node scripts/validate-v214.mjs` and `node scripts/test-v217-conversation.mjs`.
Prefer a Vercel Preview deployment before `npx vercel --prod`. Do not enter real customer data into test conversations.

## Momo sales (PT and EN)

1. Ask a simple question about the product. Expect a short, natural answer without a habitual greeting, list or filler question.
2. Describe a business but give no URL. Expect useful business-related examples and, when relevant, an invitation to share the website; no premature request for email/phone.
3. Send a safe **public test website URL**. Verify the existing website analysis runs and the reply cites only observed site details, then connects two or three findings to possible Momo use cases. The assistant may ask if the suggestions make sense, but should not request contact on the sole basis of receiving the URL.
4. Respond positively to those suggestions and ask to progress. Expect one low-friction request for a name (if still unknown) and a single preferred contact method (email **or** phone); do not require both.
5. In another new conversation, send a URL **and** explicitly ask for a proposal in the same message. Expect a site-specific explanation **before** a contact request in that same reply.
6. Ask a second question after a website analysis without repeating the URL. Expect an answer to the new question, not the same site audit again.
7. Test a URL the analyzer cannot read. Expect an honest limitation and no fabricated findings.
8. Ask for an unapproved price, contractual term or live integration. Expect no invented numbers, commitments or claims of access.
9. Provide an email only. Expect it to be treated as contact information, never as a website to analyse.
10. Repeat in English, ensuring the style remains consistent and professional without mirroring slang.

## Momo Support

- Ask a simple portal how-to: expect a concise answer from approved support knowledge without a ticket.
- Ask an unanswerable minor factual question: expect a clear limit rather than an invented answer; team follow-up only if appropriate.
- Request a human, report a serious bug or submit a privacy request: expect the existing ticket creation/escalation flow to remain functional.
- Verify the response still respects the structured JSON decision schema internally and never claims a human has already read the ticket.

## Client agents

- In Admin Preview, check existing friendly, direct and formal tone settings with the same factual question. All should be natural and concise while preserving their configured tone.
- Check the passive, proactive and disabled contact-capture modes. The new style must never override those settings.
- Check that unconfirmed prices, availability, bookings or integrations are not invented, and that the widget still shows the AI transparency label.

## Technical safeguards

- Confirm `app/legal/page.tsx` still uses `border-white/6`, not the Tailwind arbitrary-value variant.
- No Supabase migration or Vercel environment changes are required for this version.
- The deterministic regression test verifies branching/prompt construction, **not** the quality of live model responses or actual website reachability. Complete manual QA before production deployment.

# Momo v2.22 - Agent Tone Comparison

This release updates the four existing client-agent tone profiles and adds an explicit four-way comparison in the Admin and Client Portal. It does not change Momo Sales or Momo Support, language entitlements, lead capture, pricing, migrations or live business integrations.

## Local validation

From the complete Momo project after replacing the supplied folders:

```powershell
node scripts/test-v217-conversation.mjs
node scripts/test-v221-language-policy.mjs
node scripts/test-v222-agent-tones.mjs
npm run lint
npx tsc --noEmit
npm run build
```

The comparison endpoint intentionally makes up to four OpenAI text-generation calls per click. It is available only to authenticated Admin users or active client owners authorized to preview that organization, and is limited to six comparisons per organization per 15 minutes in production. It does not write chat history or leads.

## Manual acceptance test before production

1. In `/portal/agent` for a test organization, choose each of the existing four tones. Check that the descriptions differ. Do not save anything yet.
2. With a known and approved Knowledge Base, click **Comparar respostas** using the pre-filled question. Check four cards appear, each answering the same question with a distinct register. Verify no card invents services or prices and that the response is in the organization's primary language.
3. Click **Escolher este tom** on one card. Confirm the selector changes. Save the configuration and return to the page. Confirm that tone remains selected and is used in the ordinary Agent preview.
4. Repeat the comparison in the Admin's client Agent page. Confirm that it is available there too.
5. Check that changing unsaved objectives or custom instructions requires saving first; comparison must use the currently saved settings and must not create leads or tickets.
6. In a PT-only organization, repeat the recommended question in Portuguese. Repeat with an EN-only organization using the English recommended question. Confirm the language access rules from v2.21 continue to work in the normal Widget.
7. Confirm a normal Widget reply still follows the saved tone and the existing goal, fallback and contact rules, and that the comparison itself does not change the active tone.

## Deployment

After validation, use the normal workflow:

```powershell
npm run build
npx vercel --prod
```

No Supabase migration or Vercel environment change is required. Keep the existing published AI-disclosure label on the widget.

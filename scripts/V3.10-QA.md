# Momo v3.10 - Password Change & Support Secret Redaction

## Scope

- Owners and Members can change their own Portal password from My account.
- Current password is re-verified before the Auth password is changed.
- Momo Support knows the password-change flow and can recommend it after suspected unauthorized access.
- Passwords, tokens, API keys and other recognizable credentials are redacted before Support AI/retrieval calls and before Support ticket messages/context are persisted.
- The model reply, ticket subject and AI summary also receive defensive redaction.

## Manual checks

1. Log in as an Owner and change the password from My account. Sign in with the new password afterwards.
2. Repeat with a Member account.
3. Try an incorrect current password. The change must be rejected.
4. Try mismatched new-password confirmation. The change must be rejected.
5. Ask Momo Support: `Acho que alguém entrou na minha conta sem autorização.` It should recommend changing the password in My account and create a high-priority ticket.
6. Send a test support message with a clearly fake labelled secret, for example `password: TEST_ONLY_SECRET_123`. If a ticket is created, inspect both its initial message and context snapshot. The secret value must be replaced with `[REDACTED]`.
7. Confirm no Owner-only restriction exists on the password form; it is personal account functionality for both roles.
8. After running the v3.10 SQL migration, inspect the earlier test ticket that contained a labelled password. The stored password value should have been replaced with `[REDACTED]`.

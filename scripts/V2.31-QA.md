# Momo v2.31 | Support unread alerts: QA

## Mandatory install order

1. Back up the production Supabase database, and confirm the target project.
2. Run `supabase/v2.31-support-unread-alerts.sql` **once** in the Supabase SQL Editor. The first installation marks historical tickets/replies as already read, to avoid a large initial backlog. Reruns do not re-seed users.
3. Run `supabase/v2.31-readonly-support-alerts-verification.sql`. All eight columns should return `true`.
4. Extract the v2.31 ZIP at the Momo project root, then execute the static tests, ESLint, TypeScript and build before deploying.

```powershell
node scripts/test-v231-support-alerts.mjs
npm run lint
npx tsc --noEmit
npm run build
npx vercel --prod
```

## QA scenarios (use disposable users and tickets)

- **Admin, new ticket:** After initial installation, create a new ticket from a client. The Admin's Support label shows a small exclamation mark, including after refreshing the page. Open the Support list: the ticket is labelled "Por ler".
- **Admin, opened ticket:** Open its conversation. The ticket's unread label and the Admin badge disappear after the read receipt is saved. Other unread tickets remain notified.
- **Admin, new client reply:** Reply from the customer to a ticket the Admin has read. The Admin badge reappears without requiring logout. It polls every 45 seconds while the tab is visible, and also refreshes on focus or navigation.
- **Admin, multiple users:** Log in as another admin in a separate browser profile. One admin reading the ticket must not mark it as read for the other admin.
- **Portal, team response:** Send a team response from Admin. Every current member of the correct client company who hasn't opened it sees the badge; customers in other companies do not. Clicking the corresponding ticket clears that user's alert only.
- **Portal, own messages:** A new ticket or a customer's own message must not trigger a portal badge. A team reply should, even if an email notification fails.
- **Portal, multiple users:** Two members of the same organisation each see the reply. Opening it as one member must not clear the other member's badge.
- **Concurrency:** Post another incoming message while the ticket is opening (after the page fetched its messages, before the read marker returns). The new message should remain unread until the page actually displays it. Repeated/out-of-order read receipts must not regress the last-read timestamp.
- **Resolved tickets:** A resolved ticket shouldn't remain in the Admin's active unread queue. An additional customer reply that reopens it should appear. A portal user should still be notified of a team reply even if the ticket is subsequently marked resolved.
- **Mobile:** Make sure the exclamation badge is visible above Support on both Admin and Portal navbars and that horizontal scrolling still works.
- **Security:** From a Portal session, attempting to mark a ticket from another organisation should return an error and must not affect that other organisation's notifications. An anonymous API request must return 401.

**Notes:** The nav badge is for unread events, not all open tickets. Mail notifications are unchanged. Without the SQL migration, notifications are unavailable; an error is logged rather than blocking access to the dashboards.

# Momo v2.32: sales conversation without repeated steps

This is a targeted conversational prompt/state refinement. There is no database migration, change to billing, widget agents, client Portal Support or website crawler.

## Manual end-to-end QA on the public Momo sales chat

1. Start a fresh conversation: "Sou um centro de explicações". Momo should give concise business-relevant ideas and optionally invite one website link. Avoid multiple sales confirmation questions.
2. Say "Não tenho um site". Momo should acknowledge that a site is optional, not list the same explanation use cases again or insist on a website.
3. Say "Afinal tenho site e é este https://<a real site you control>". Confirm that the existing crawler actually analyses public pages. The reply should mention only findings supported by the analysis, prioritise new findings over previously stated generic suggestions and end **in the same reply** with an optional name + email-or-phone invitation. It should not ask only whether the ideas are useful.
4. On a separate fresh chat, share a URL without expressing any purchase intent. The CTA should remain an invitation, not a claim that a proposal is being prepared or that the visitor consented to follow-up.
5. Reply "sim" to the invitation. Momo should ask only for missing contact details, without restarting its explanation or asking for yet another yes.
6. Supply an email or phone. Confirm the lead is saved, the contact is acknowledged and the assistant does not ask for both email and phone.
7. Repeat with an explicitly requested proposal and a new URL in the same message. Momo should analyse first and invite the required contact in the same answer.
8. Repeat with a site that cannot be fetched and check that Momo does not invent website observations. Repeat after providing a name or a contact to ensure Momo does not request known details again.

These automated checks validate state and prompt rules, not stochastic model output. The live sequence above is required before closing the release.

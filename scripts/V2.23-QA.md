# Momo v2.23 - Chat window size QA

## Before deployment

1. Back up the database as usual and run only `supabase/v2.23-widget-panel-size.sql` in the correct Supabase project's SQL Editor.
2. Confirm the two new `widget_configs` columns and defaults using the following read-only SQL:

   ```sql
   select column_name, column_default, is_nullable
   from information_schema.columns
   where table_schema = 'public'
     and table_name = 'widget_configs'
     and column_name in ('panel_width', 'panel_height')
   order by column_name;
   ```

3. Run `node scripts/test-v223-widget-size.mjs`, `npm run lint`, `npx tsc --noEmit`, and `npm run build`. Only then deploy.

## Manual checks (Admin + Portal)

- On an existing organization open Widget settings. Confirm 390 px width and 570 px height before any changes.
- Move both sliders to their maximum (520 x 760). Live preview must reflect both dimensions.
- Click **Original size**, confirm 390 x 570, then select a larger size again and save.
- Refresh Widget settings in both Admin and Portal. Confirm both display the same persisted dimensions.
- Open the actual embedded widget on a desktop test website. Confirm the iframe grows with the configured panel and no part is clipped.
- Test both `left` and `right` positions, plus opening/closing the widget and the hover label.
- On a narrow phone and short mobile landscape viewport, confirm the panel fits inside the available viewport, content is scrollable and launcher/close button still work. Narrow screens may display smaller dimensions temporarily, but never change the saved values.
- Try submitting below-min and above-max values directly. The server must clamp to the documented 390–520 / 570–760 bounds; the DB also rejects out-of-bounds writes.
- Run the existing regression checks and confirm none of the Agent, lead capture or Support flows changed.

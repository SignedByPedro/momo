# Momo v3.0 - Knowledge QA & Product Audit

## Objetivo

Stress test do conhecimento e comportamento do Momo Sales e do Momo Support antes de acrescentar novas funcionalidades.

A versão v3.0 não altera a aplicação. Este pacote define a matriz oficial de QA, valida o alinhamento estático das políticas e serve para testar as respostas reais dos dois agentes.

## Release gate

- 100 cenários no total: 40 Momo Sales + 60 Momo Support.
- Todos os cenários `critical` têm de passar.
- Objetivo mínimo: 95/100 no total antes de fechar a v3.0.
- Uma falha repetida da mesma regra conta como problema sistémico, mesmo que a pontuação total seja >=95.
- Nenhuma resposta deve usar o caractere `—`.
- O agente não pode inventar preços, integrações, SLAs, métodos de pagamento, limites de plano ou funcionalidades futuras.

## Como testar

1. Confirmar que v2.33 e v2.34 foram aplicadas e ambas as Knowledge Bases foram reindexadas.
2. Usar conversas novas para cada grupo de testes sempre que o contexto de uma conversa anterior possa influenciar a resposta.
3. Para os testes de Momo Sales, usar o widget/landing público.
4. Para os testes de Momo Support, usar uma conta de cliente de teste no Portal.
5. Registar PASS/FAIL e copiar a resposta apenas quando falhar ou parecer duvidosa.
6. Em testes que criam tickets, usar uma organização/conta de teste e limpar os tickets depois.

## Critérios gerais de PASS

- A resposta está factualmente alinhada com a Knowledge Base atual.
- Não inventa informação ausente.
- Não cria ticket quando a regra diz `false`.
- Cria/propõe ticket quando indicado, com categoria/prioridade coerentes.
- Responde de forma natural, curta e sem repetição desnecessária.
- Se houver dúvida factual relevante, assume a limitação ou encaminha, em vez de adivinhar.

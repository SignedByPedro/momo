# Momo v2.33 - Knowledge Foundation

## Goal

Bring the two platform knowledge bases up to date with the client-facing product behaviour implemented through v2.32.

## Scope

### Momo Sales

The public sales knowledge now covers:

- What Momo is and the monthly service model
- How pricing is scoped without inventing exact prices
- Implementation flow
- Base language vs paid multilingual upgrade
- Website analysis and its limitations
- Starting/configuring Momo without a public website
- Client Knowledge Base behaviour
- Widget customization
- Client Portal overview
- Client support model
- External integrations
- Human follow-up
- Lead handoff after demonstrated interest

The existing internal draft entries for billing, cancellation, privacy, retention, SLA and onboarding timing remain drafts. This version does not invent those policies.

### Momo Support

The support knowledge now covers:

- Product and Portal overview
- Company settings
- Primary-language policy and request flow
- Agent identity, objective, goals, contact capture and test chat
- Tone comparison
- Base language vs multilingual entitlement
- Knowledge Base management and website analysis
- Widget appearance, panel size, publication, install and troubleshooting
- Conversations and leads, including compact display of long URLs
- Team roles, seat limits and Owner/Member removal rules
- Personal account deletion and last-Owner safeguard
- Tickets, client resolution, reopening, unread alerts and email notifications
- Escalation rules
- Organization data export and verified deletion requests
- 90-day normal cancellation recovery flow
- Persistent login and Enter-key login behaviour
- Billing/commercial questions that require the team

## Important separation

The two agents still use separate `agent_key` values in `knowledge_entries`:

- `momo-sales`
- `momo-support`

Shared facts are intentionally duplicated where both agents need them. This avoids changing the current retrieval architecture while keeping each agent's scope explicit.

## Reindex requirement

The SQL migration sets the embedding of every inserted/updated public entry to NULL so no old vector can represent new text. After running the migration, reindex both knowledge bases from Admin before testing.

## Policies intentionally not finalized

Do not publish exact information for the following until it has been approved by the business/finance/legal process:

- Exact prices
- Billing dates and payment methods
- Failed-payment rules
- Contract minimum terms or notice periods
- Human-support SLA
- Detailed legal/privacy wording beyond implemented product workflows
- Standard onboarding duration
